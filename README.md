# Clickable Mail

Внутренний конструктор писем: письмо собирается из блоков (компоненты из Figma-файла Mail-Autocode), настраивается и выгружается
в HTML для рассылки — его собирает автоматизация n8n тем же генератором, что и у плагина Figma.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # проверка типов + сборка в dist/
npm run test       # все тесты (unit в Node + browser в Chromium)
```

Браузерным тестам нужен Chromium для Playwright. Если его нет: `npx playwright install chromium`.

## Устройство

- `src/model` — модель письма (`types.ts`), каталог блоков, клиенты, шаблоны, пресеты (`catalog.ts`).
- `src/store` — состояние редактора с историей (zustand + zundo), UI-состояние, черновики в IndexedDB (временная замена бэка).
- `src/email` — рендер письма в HTML для превью (iframe). Эта же разметка — источник для планировщика экспорта.
  `src/email/plan` — письмо → `plan` v5 плагина Figma и картинки (см. «Экспорт»).
- `src/editor` — экран редактора: библиотека, холст с оверлеем, слои, инспектор, экспорт.
- `src/home` — стартовый экран: клиент → шаблон, черновики.
- `src/ui` — общие контролы.
- `n8n/` — воркфлоу для n8n (`clickable-mail.json`), инструкция по подключению и инструменты (`n8n/README.md`).

## Экспорт

HTML для рассылки приложение само не верстает. Цепочка такая:

1. Письмо рендерится в скрытом iframe 600px той же разметкой, что в превью.
2. Планировщик (`src/email/plan/planner.ts`) строит `plan` в формате плагина Figma v5. Тексты остаются живым текстом.
   Hero, баннеры, таймер и подложки кнопок становятся картинками, рамки и плашки — CSS.
   Что именно перед ним, планировщик понимает по атрибутам `data-plan` в рендерах блоков. Их надо сохранять при правках разметки.
   Hero — одна картинка, кликабельны только логотипы (прозрачные ссылки поверх). В хедере приложения это его лого и лига;
   в режиме «Без хедера» логотипы нарисованы на картинке — их место задают «Зоны клика» в настройках hero
   (рамки на превью тянутся мышью; для картинок шаблонов размечены заранее, `src/model/heroZones.ts`).
3. Картинки снимаются в 2× (`raster.ts`) и получают имена с отпечатком содержимого: `btn-3f9a2c.png`.
4. JSON (поля как у плагина + `source`, `preheader`) уходит на вебхук n8n. Автоматизация `n8n/clickable-mail.json`
   заливает картинки на FTP (`email_images` на demo.promo), собирает HTML генератором `html_gen` плагина и возвращает его.
5. Окно экспорта отдаёт этот HTML: **ZIP** (HTML + `images/`), **HTML** (картинки по ссылкам), **Код** (в буфер).
   Результат запоминается для версии письма: письмо не меняли — повторно в n8n не идём.

Адрес вебхука — `VITE_N8N_WEBHOOK_URL` в `.env.local` (образец — `.env.example`) или `DEFAULT_WEBHOOK` в `src/email/n8n.ts`.
Пока его нет, экспорт недоступен. Как подключить автоматизацию — `n8n/README.md`.

«Скачать JSON» в окне экспорта сохраняет ровно тот запрос, что уходит в n8n. Без n8n из него собирается HTML:
`node n8n/tools/run-html-gen.ts письмо.json n8n/out/письмо`.

Браузерные тесты (`npm run test:browser`) собирают все шаблоны генератором и кладут результат в `n8n/out/<шаблон>/`:
`compare.html` показывает превью и HTML рядом (открывать через `npm run dev`: http://localhost:5173/n8n/out/sport-match/compare.html).
